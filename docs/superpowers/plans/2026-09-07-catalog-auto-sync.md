# 模型名单自动同步

目标：名单按同一版本更新，失败和乱序响应不能把已可见模型误隐藏。

- 官方模型、暂停、服务专用、God-only 名单来自同一目录快照；固定名单仅作无有效资料时的兜底。
- 官方源缓存 5 分钟，失败退避 1 分钟；面板可见时每分钟轻量读取目录，重新聚焦时补一次。账号完整探测仍为原来的每小时一次。
- 已有成功缓存时，失败不能用旧 Release 或缺失控制名单的结果覆盖它。
- 目录响应带递增版本；前端拒绝较旧版本，config 仅能在目录尚未加载时提供兜底。
- 保留限定模型的 Premium/独立可用额度条件、Key 白名单限制和明确停用规则。思考等级/上下文资料快照不参与可见性判断。
- 验证覆盖：官方解除限制、未知名单格式、刷新失败、返回乱序、冷启动旧 config、轻量轮询不调用账号探测。

部署与验证（2026-09-07）：

- 已在容器 `ciallo-freebuff-proxy` 激活 `worker.js` 和 `web/app.js`；激活前确认 Codebuff 在途连接为 0，保留原文件权限及本地备份，未写容器宿主机文件。
- 容器 Node 22 的自动同步专项 14 项通过；本地基础 unit 194 项、其余回归 269 项通过。浏览器验证覆盖 Muse 冷启动误藏、旧响应回灌、Key 白名单保留及轻量轮询。
- 暂存版本读取当前官方公开源成功，暂停、服务专用及 God-only 名单均完整解析。没有执行模型生成或账号探测。
- 公网 `/healthz`、`/v1/models` 均为 200，Muse 1.3 在可见模型中；四份控制名单没有与可见模型冲突。
- 连续读取时响应 `revision` 递增、同一目录的 `updatedAt` 保持一致，`stale=false`，响应含 `Cache-Control: no-store`。
- 公网 `/static/app.js` SHA-256 与已测试版本一致。已有页面需要 F5 一次加载新增定时同步逻辑。
- 部署清单和核验记录：工作区 `.local/catalog-auto-release.json`、`.local/catalog-auto-public-preflight.json`、`.local/catalog-auto-live-verification.json`。
