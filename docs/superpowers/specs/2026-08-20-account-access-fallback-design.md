# 账号授权探测与回落设计

## 目标

自动出站必须尽快找到该账号实际可用的 US/SG 节点，同时不能因后台复验把已有可用路由标成“验证中”或阻断业务。分享 Key 的显示只保留必要信息。

## 授权分级

每个候选节点只请求一次 `/api/v1/freebuff/session`，按以下顺序检查 `rateLimitsByModel`：

1. 高级授权：`deepseek/deepseek-v4-pro`，随后 `openai/gpt-5.6-luna`。
2. Free 授权：`deepseek/deepseek-v4-flash`，随后 `mimo/mimo-v2.5`。

高级模型必须有正数额度且仍有剩余额度。Free 的 STANDARD 计数不能可靠表示耗尽，因此模型行存在且 `limit > 0` 即视为可用。验证结果记录授权级别和命中的模型；Free 结果 15 分钟过期，高级结果沿用现有缓存周期。

## 可用性与速度

- 已验证路由过期后继续承载业务，并在后台复验；面板仍显示就绪。
- 冷启动尚无可用路由时不把未验证节点用于业务。
- 各账号的初始化任务并发启动；共享 probe lane 继续串行切换节点，避免相互覆盖。
- 某账号在业务请求中报告本地 `ACCOUNT_EGRESS_UNAVAILABLE` 时，只跳过该账号并尝试账号池中的下一个账号。
- 自动订阅刷新完成后主动重建账号路由，避免下一次业务请求承担恢复工作。
- 不改 Key 并发、每日会话计数或上游 session 锁定逻辑；真实诊断已证明目标 Key 的 Luna 失败发生在建会话之前。

## 面板

- 分享 Key 只显示前 8 个字符与省略号，例如 `fbk-IQRk…`。
- “今日 / 累计”后的进行中状态只显示绿色数字，例如 ` · 1`，通过悬停和可访问名称说明“进行中”。
- 删除推广链接常量及授权前的推广页预打开，仍安全打开后端返回的官方 OAuth 地址。

## 验证

先用测试锁定分级优先级、Free 15 分钟过期、旧路由复验期间可用、跨账号回落和 UI 文案，再做最小实现。完整离线测试通过后热更新容器，并用脱敏输出验证目标 Key 的实际 Luna 请求。
