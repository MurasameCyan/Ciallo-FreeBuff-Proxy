# 概况统计数据持久化设计

## 目标

在面板「概况」标题右侧增加一个无文字胶囊开关，让管理员选择是否将概况累计统计保存到服务端数据目录。默认关闭，保持现有行为与隐私边界。

## 范围

持久化以下 `/usage` 概况数据：请求总数、成功/失败数、各类 Token 累计值、各模型成功调用次数、进程启动时间与最后请求时间。调用日志明细及账号凭据不纳入持久化。

## 方案

### 服务端

- 在现有 `FREEBUFF_DATA_DIR` 下新增统计设置/数据文件。
- 增加管理 API：读取当前设置与统计数据、切换持久化开关。
- 统计开关默认 `false`；关闭时继续在内存中累计，但不写入磁盘。
- 开启时加载已有统计并继续累计；每次成功调用更新内存累计值，并以安全写入方式保存。
- 关闭后保留已有文件，避免误操作导致历史数据丢失；再次开启可继续使用。
- 旧版本没有文件时按空统计启动，不能因统计文件损坏阻塞服务启动，需回退为空统计并记录错误。

### 前端

- 在概况卡 `.card-head` 标题右侧放置现有 `.switch` 风格的胶囊开关。
- 开关只显示轨道和滑块，不显示可见文字；保留 `sr-only` 无障碍标签。
- 初始状态由服务端配置决定，默认关闭。
- `title` 悬停提示明确写出「持久化统计数据（默认关闭）」；点击后立即调用管理 API，并在失败时恢复原状态、提示错误。
- 开关不改变调用日志实时刷新，也不触发上游请求。

## 数据流

页面加载 → `GET /_api/usage-persistence` → 设置开关状态与概况数据；
开关点击 → `PUT /_api/usage-persistence` → 服务端更新设置；
成功调用 → 现有 usage 累计逻辑更新内存 → 仅在开关开启时写入统计文件。

## 错误处理与兼容

- 未登录请求继续返回现有鉴权错误。
- 持久化文件不可读或 JSON 无效时使用空统计，不影响代理接口。
- 磁盘写入失败时保留内存数据，API 返回明确错误；前端恢复开关状态。
- 现有 `/usage` 响应结构保持兼容，新增设置字段也不能破坏现有客户端。

## 测试

- 服务端：默认关闭、开启/关闭、重启加载、损坏文件回退、写入失败不阻断内存统计。
- 前端契约：开关位于概况标题右侧、无可见文字、默认关闭属性与悬停提示、调用正确 API、失败恢复状态。
- 回归：现有 unit、proxy、web-layout 测试全部通过。
